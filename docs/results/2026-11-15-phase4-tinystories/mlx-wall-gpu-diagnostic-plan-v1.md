# Request-aligned Metal activity diagnostic

The existing [read-only observer](mlx-gpu-observer-v1.md) records system-wide accelerator snapshots but cannot associate them with individual requests from the ordinary lifecycle binary. This diagnostic applies `tools/bench/phase4_wall_markers.patch` after the hybrid normalization patch in an isolated checkout. It adds wall-clock request start, sampler-return and end timestamps to the existing 35-request lifecycle benchmark; no production source or model algorithm changes. The prior hybrid candidate's Linux full CUDA checks and focused retained-output checks remain the applicable Linux evidence for its unchanged model; formatting and `cargo check -p ncm-model` passed for this isolated copy. The Mac-only marked example has not yet been compiled or run.

`tools/bench/analyze_phase4_gpu_activity.py` rejects incomplete or nonmonotone request sequences, absent GPU observations and wall/monotonic duration differences above 20 ms, then associates snapshots by their query-end timestamps. This 20 ms is a diagnostic clock-consistency bound, not a numerical or performance tolerance. Synthetic alignment and rejection checks pass. GPU utilization is system-wide, its averaging window is not calibrated, and the last-submission PID does not attribute GPU time or establish cause. Wall-clock adjustments and observer overhead can affect the diagnostic.

On available Metal hardware, compare the marked binary with the same unmarked hybrid binary using the existing identical cache and lifecycle policy, enabling the optional GPU observer. Analyze the marked process only and preserve all results, including absent slow requests. This captures new request-aligned GPU context; it is not a performance gate, an exclusive-device measurement or a reason to discard any earlier failure.
