# TinyStories: user-accepted exceptions before XSum

After the numerical and latency investigations, the user chose to proceed to XSum with these TinyStories limitations recorded. This is an explicit, scoped acceptance of the remaining exceptions for advancement; it does not alter the numerical band, convert failed comparisons to passes, establish a cause, or qualify the remaining profiles.

- In five fixed-code 16-row traces, Rust MLX had 1,131 generator values outside the accumulated CUDA-relative band of 293,601,280 checked values; Python MLX had 1,124, with 1,113 positions shared. The 18 Rust-only crossings were 1.000036–1.060243 times the band, and the largest excess was `4.265e-5`. Checked generator decisions and final IDs matched on those inputs. These are diagnostic exceptions, not numerical parity passes. See [overlap](mlx-outlier-overlap-v1.md) and [Rust-only magnitudes](mlx-rust-only-outliers-v1.md).
- An earlier Rust Metal candidate had multi-second latency outliers and a failed batch-128 performance comparison. The exact cause remains unknown. In the later [guarded production candidate comparison](mlx-generator-qk-rope-portable-python-v2.md), Rust had lower measured median, pooled p95, process RSS and MLX peak than Python at each of batches 1, 4, 32 and 128; no Rust trial exceeded four seconds, while Python exhibited a tail. This later evidence does not erase the earlier failure or prove the tail cannot recur. Hardware counters, process activity, cache-policy and memory-scope limitations remain in the reports.

The [Linux strict-cuDNN comparison](cuda-safe-split-performance-v1.md), scored quality evidence and [Metal integration record](generator-qk-rope-integration-v1.md) retain their original scope and limitations. Later changes must still run the full preceding regression suite, Linux/CUDA before MLX, and report any new failure independently. This acceptance does not extend the Python numerical tolerance or apply to other workloads, future changes, hardware or performance cells.
