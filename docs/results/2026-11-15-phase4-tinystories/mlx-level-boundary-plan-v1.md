# Isolated generator level-boundary experiment

The hybrid normalization candidate's [batch-128 comparison](generator-hybrid-norm-mlx-large-performance-v1.md) had a cluster of long requests and did not establish its cause. A targeted scheduling experiment tests whether explicitly materializing cumulative generator state at each level changes Metal latency or memory. The proposal does not change the upstream equations, random-word generation, sentinel validation or sampling algorithm. It adds synchronous MLX execution boundaries and therefore can change scheduling and throughput; it may also change floating-point evaluation and memory behavior. It is not a proven fix.

Apply `tools/bench/phase4_generator_hybrid_norm.patch` to an isolated checkout, then `tools/bench/phase4_generator_level_boundary.patch`. The latter adds a default no-op generator hook, called after each cumulative level update; the MLX backend evaluates that state synchronously. CUDA retains the default no-op. Keep this out of production until correctness, quality and both hardware gates are demonstrated.

On Linux first, the isolated candidate passed `cargo fmt --all --check`, the pinned CUDA Sudoku generator golden and the strict-cuDNN 128-row TinyStories retained code/ID check. The exact command used `cargo test -p ncm-backend-cuda --release --features cuda-cudnn --test generator_golden --test phase4_fused_norm_probe -- --include-ignored` with the pinned local artifact and cuDNN paths. Log `reports/phase4-level-boundary-cuda-v1.log` has SHA-256 `337dad46c460938e49e8ae5234c1cf3215c605952c5e66782981f22a42146938`. The CUDA test hook is a no-op; this limited screen is not the full CUDA gate.

On the Mac, first verify the same patched sources and compare seeded codes and IDs with the hybrid candidate. Then use a short old/new batch-128 screen with identical cache and timing policies. Preserve failures, memory counters and activity observations. A promising screen would still require full CUDA then MLX checks, expanded numerical and quality evidence, and a source-bound Python comparison. A successful short run cannot erase earlier tail failures or establish their cause.
