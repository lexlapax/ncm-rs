# Generator Q/K rotary and GELU integration

The production candidate applies the already screened hybrid normalization, compiled exact-erf GELU with an initialization error guard, and fused weighted RMS plus split-half rotary operations. CUDA's trait defaults retain the existing composed operations; MLX selects the same measured batch-sensitive paths. The GPU kernel checks SIMD width and provides a scalar reduction for other widths. This does not alter the pinned upstream, artifact, model equations or numerical thresholds. The scalar branch has been forced on the test Mac but not run on actual non-32-wide hardware; a real MLX compiler-cache failure has not been injected.

The six relevant production source/test files match the [fully validated isolated source](mlx-generator-qk-rope-portable-screen-v2.md) byte for byte except for the first module-description comment. The isolated candidate passed full CUDA then MLX checks, same-device fixed-code diagnostics and a nonblind five-seed quality retest; its [three-process Python comparison](mlx-generator-qk-rope-portable-python-v2.md) favored Rust in latency and measured memory at all representative batches. Those measurements used the isolated executable and do not independently measure a production-checkout executable. The upstream CUDA-reference floating-point diagnostic exceptions and previous intermittent tail remain recorded.
