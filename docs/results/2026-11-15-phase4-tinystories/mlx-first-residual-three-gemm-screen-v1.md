# First-residual three-matrix candidate: full-model rejection

The isolated [candidate](mlx-first-residual-three-gemm-plan-v1.md) passed its synthetic real-Metal operator comparison and focused CUDA generator checks. The attractive 128-row Python operator result did not carry over to the existing 16-row fixed-code full-model diagnostics.

Across five 16-row traces, generator-level and final logits had 117,505 values outside the existing accumulated diagnostic band against pinned Python CUDA, compared with 1,131 for the preceding production candidate. Against the same-device Python MLX adaptation, 120,280 values were outside the band, compared with zero previously. One generator level-10 argmax changed in seed 102, and three codec codes changed in seed 103; the checked final output IDs still matched. The seed-103 level-0 reconstruction already had 353 values outside the band versus zero previously. These are failures under the existing diagnostic checks; no tolerance was changed.

The candidate uses the altered first refinement in both codec encoding and reconstruction, so the changed codec codes are material. Batch and reduction shape can affect numerical behavior; the earlier 128-row operator result is not a substitute for this 16-row full-model evidence and does not establish the cause of the regression. The candidate is rejected and remains isolated. Stochastic-quality and end-to-end performance runs were not started. A future narrower shape-specific proposal would require independently qualified traces and must not hide this failure.
