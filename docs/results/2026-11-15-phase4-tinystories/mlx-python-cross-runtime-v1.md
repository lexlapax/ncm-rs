# Direct Python MLX versus Python CUDA generator traces

Five retained 16-row fixed-code traces were compared directly: the qualified same-device Python MLX adaptation against pinned original Python CUDA. The comparison covers 11 generator-level logits and final logits: 293,601,280 floating values. It uses the unchanged diagnostic band `atol=5e-4, rtol=2e-4` and compares last-axis argmaxes.

| Seed | Python MLX outside band | Rust MLX outside band | Python MLX changed argmaxes |
| ---: | ---: | ---: | ---: |
| 100 | 148 | 150 | 0 |
| 101 | 517 | 522 | 0 |
| 102 | 162 | 165 | 0 |
| 103 | 140 | 138 | 0 |
| 104 | 157 | 156 | 0 |
| Total | 1124 | 1131 | 0 |

The Python MLX adaptation itself exhibits nearly the same number and per-seed distribution of outside-band values as Rust Metal when both are compared with the same pinned CUDA traces. Levels 8, 10 and 11 account for 930 of the 1,124 Python outside-band values. This supports a cross-runtime or adaptation contribution; matching counts do not prove the same positions differ, establish which operation causes the differences, or establish a numerical pass. The Rust values are from the [previous fixed-code reports](mlx-generator-qk-rope-screen-v1.md), not generated by this comparison. The adaptation's other merged tensors include CUDA-copied values and were intentionally excluded. No threshold changed.

The CPU-only comparator `tools/bench/compare_phase4_python_traces.py` checks tensor metadata, bounds, shape and finite values, then hashes itself and both traces before and after each comparison. Source and inputs were stable.
