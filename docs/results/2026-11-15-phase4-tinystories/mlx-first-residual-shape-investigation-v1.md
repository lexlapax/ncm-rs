# First residual: batch shape and Rust/Python comparison

The rejected three-matrix candidate worsened full-model diagnostics despite improving an earlier isolated 128-row residual comparison. To investigate whether MLX batch size explains the difference, the Python MLX operator screen was repeated at batch 16 on the first 16 rows of the same retained CUDA input. The reference outputs were captured by CUDA at batch 128; this is not a fresh CUDA batch-16 oracle. The existing accumulated diagnostic band was unchanged.

For the 786,432 blended output values, the ordinary convolution had 1,940 values outside the CUDA band and the three-matrix variant had 1,294. Computing the same comparison over the first 16 rows of the earlier batch-128 MLX captures gives exactly the same counts and maximum absolute differences: 0.01123046875 and 0.00927734375 respectively. Equal counts alone do not establish bitwise equality across batch shapes or rule out shape effects on other inputs.

The direct Rust probe `tools/bench/phase4_mlx_first_residual_probe.rs` was built in the isolated rejected candidate and run on the same 16 input rows and pinned weights. Its captured input and blended output safetensors file has SHA-256 `73708898db416c0b84a98dc5d4321e1d652c63d6c95f2d14590240c3e0b53a68`, exactly matching the independently produced Python MLX three-matrix capture. Thus those files are byte-identical for this input; this does not prove equivalence for every input. The implementation's mathematical rearrangement, rather than a demonstrated Rust transcription discrepancy, remains a plausible cause of the full-model sensitivity. The earlier model regression, including changed decisions, remains decisive; the candidate is rejected.

The Python screen used `tools/reference/phase4_mlx_residual_variants.py --batch 16`, artifact `artifacts/canonical/tinystories-phase4-v1`, and the retained CUDA reference SHA-256 `b320d70ba0f2393cd1276200db064d477d000c87241c6541c680699391f8b085`. Its summary is retained as `reports/phase4-mlx-residual-variants-b16-v1.json`, SHA-256 `58b4b58185d6dc6ea4a9586c62a3ca7eaf50bc9ede1945f54cb448c1850834eb`. The same-row comparison used the retained batch-128 captures listed in the [original screen](mlx-residual-variants-screen-v1.md), verifying identical input rows and counting `abs(actual-reference) > 5e-4 + 2e-4 * abs(reference)` in FP64.

The first isolated build omitted the documented prebuilt MLX environment and failed because the Metal compiler was unavailable; a second build identified a missing `WeightBackend` import. The corrected probe compiled in release mode with the documented prebuilt environment and ran on real Metal. The copied CUDA reference and temporary probe source were removed from the Mac after verification. No production model, tolerance or system policy changed. This targeted operator check does not qualify end-to-end quality, performance, memory, or the unresolved latency tail.
