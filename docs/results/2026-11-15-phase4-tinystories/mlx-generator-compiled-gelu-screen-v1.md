# Compiled generator GELU screen

The isolated [compiled-GELU candidate](mlx-generator-compiled-gelu-plan-v1.md) uses MLX shape-independent compilation of the existing exact-erf expression for large width-3072 activations, on top of hybrid normalization. The focused CUDA Sudoku golden and strict-cuDNN TinyStories retained-output checks passed first. The real-Metal composed-versus-compiled operator test passed, including the checked non-finite inputs. One seed-42 batch of 128 produced codes, raw IDs, text and tokens byte-identical to the retained hybrid output. This initial check was limited; the subsequent fixed-code comparison is described below.

The isolated candidate subsequently passed the full `tools/check.sh --cuda`, followed by `tools/check.sh --mlx`, including 18 real-device operator cases on each platform. Their logs are `reports/phase4-gelu-compiled-cuda-full-v1.log` (SHA-256 `dcddbcc6d6c5c1975fadf623b485c83e1d05b848588b9869cee075e37f088fa8`) and `reports/phase4-gelu-compiled-mlx-full-v1.log` (`325a395056aa6c546accc33826ed6eb5967ea20106c1859361f10c34ee1b8d3e`, verified against the Mac). These checks do not by themselves establish model quality.

One fresh process per binary and batch ran five warmups and 30 timed generation/readback requests with the same explicit 4,096 MiB process-local cache, output drop and GPU barrier. Baseline ran first at batch 32; candidate ran first at batch 128. CPU and system-wide GPU activity observers ran throughout and may perturb timing. This is an exploratory old/new screen, not a Python performance gate or a cold-start measurement.

The candidate reduced median latency by about 7.0% and 9.5%, respectively, and lowered MLX peak in this screen. RSS was slightly higher in both cells and the batch-128 cache snapshot was higher. No request exceeded four seconds, so the screen does not establish a tail remedy. One process per binary cannot establish a general speedup; startup, compiler cache lifetime and the pinned compiler constructor's possible panic remain unresolved. RSS and MLX counters have different scopes; the cache limit is not a hard instantaneous bound.

All five official-seed 256-sample files were then captured from the compiled candidate and were byte-identical to the previously scored hybrid files on both machines. The existing [nonblind quality retest](generator-fused-norm-quality-v1.md) therefore applies to these exact sample files; this is not a fresh blind test. The capture runner's qualification input was the hybrid candidate's existing fixed-code summary, not an independent compiled-candidate numerical qualification. Candidate generator source was separately fingerprinted before and after; watched inputs and sources were stable.

Subsequent compiled-candidate fixed-code comparisons covered five 16-row development traces against both the same-device MLX adaptation and pinned Python CUDA. All ten resulting summaries were byte-identical to the earlier [fused-normalization summaries](generator-fused-norm-mlx-screen-v1.md), with stable source and input fingerprints. Thus all checked generator values were within the existing same-device diagnostic band, and all checked head argmaxes, output IDs and codec codes matched; the earlier 1,132 upstream CUDA generator/final-logit outside-band values remain. Summary equality does not prove that all underlying candidate tensors are byte-identical.
