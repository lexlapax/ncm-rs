# Compiled GELU initialization guard screen

The isolated [guard candidate](mlx-compiled-gelu-error-guard-plan-v1.md) catches compiler-constructor panics when Rust unwinding is enabled and returns a backend error. It explicitly rejects the compiled path in `panic=abort` builds, with no silent eager fallback. The focused CUDA Sudoku golden and strict-cuDNN TinyStories retained-output comparison passed before the Mac checks.

On the Mac, the focused unit test converted a simulated constructor panic to an error and accepted a successful initializer. The real-Metal composed-versus-compiled GELU operator comparison passed, including the checked non-finite inputs. A separately built `panic=abort` diagnostic invoked the large-shape GELU path and received the expected explicit rejection. A seed-42 batch of 128 from the guarded candidate was byte-identical to the retained unguarded candidate in codes, raw IDs, decoded text and re-encoded tokens; watched source, binary, library and artifact hashes were stable.

These checks do not inject an actual MLX cache-acquisition failure, test custom panic hooks or establish recovery from failures outside construction. A `panic=abort` consumer cannot use this compiled path in the proposed implementation. One seed does not establish full numerical or quality equivalence, and the guarded source has not passed full CUDA-then-Metal gates or a performance comparison. The earlier [unguarded batch-128 performance failure](mlx-generator-compiled-gelu-python-performance-v1.md) remains open; nothing is integrated.
