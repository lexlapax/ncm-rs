# Isolated compiled generator GELU experiment

After the handwritten Metal kernel could not resolve the pinned MLX error function ([failed experiment](mlx-generator-gelu-plan-v1.md)), this candidate uses MLX's previously studied shape-independent compiler for the same composed exact-erf expression. Apply `tools/bench/phase4_generator_hybrid_norm.patch` and then `tools/bench/phase4_generator_compiled_gelu.patch` to an isolated checkout. Only rank-three FP32 width-3072 activations with batch at least 16 use the compiled expression; other shapes retain the existing path. The compiled function is shared by backend clones and all arrays, including scalars, remain explicit inputs. Compiled FP32 evaluation may differ, and startup and cache costs are unknown for this generator.

The earlier [shape-independent codec diagnostic](../2026-11-11-phase2-optimization/mlx-gelu-shapeless-result-v1.md) passed focused Metal parity tests but left first-use cost, retained resources and the pinned compiler constructor's possible cache-acquisition panic unresolved. This candidate is exploratory and does not resolve those production concerns.

On Linux, formatting and the pinned CUDA Sudoku golden and strict-cuDNN TinyStories retained code/ID comparison passed using `cargo test -p ncm-backend-cuda --release --features cuda-cudnn --test generator_golden --test phase4_fused_norm_probe -- --include-ignored`; the Metal-only change leaves CUDA unchanged. The focused log `reports/phase4-gelu-compiled-cuda-v1.log` has SHA-256 `a82c6c6b980c22e1c2709bb4eb083fa351613eae751c45e94ddb681255b6bad9`. Patch replay reproduced the isolated source. These checks do not replace the full CUDA gate.
