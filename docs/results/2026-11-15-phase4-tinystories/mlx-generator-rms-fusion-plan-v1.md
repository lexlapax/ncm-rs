# Generator RMS weight-fusion experiment

TinyStories executes two query/key RMS normalizations in each of 12 transformer blocks across 11 generated levels: 264 applications per request. The current Metal implementation uses MLX's fast RMS normalization without its weight argument and multiplies the weight separately. This isolated experiment applies the existing [phase-2 RMS-affine patch](../2026-11-11-phase2-optimization/mlx-rms-affine-experiment-v1.patch) on top of the [hybrid normalization patch](generator-hybrid-norm-plan-v1.md), passing a matching one-dimensional weight directly to MLX's fast RMS primitive and retaining the broadcast fallback. It keeps the upstream normalization equation and weights but may change FP32 rounding. No performance or tail improvement is assumed.

The earlier [codec diagnostic](../2026-11-11-phase2-optimization/mlx-rms-affine-diagnostic-v1.md) passed its focused weighted-RMS test and full platform checks but did not establish a codec speedup. Its conclusion does not establish generator performance. This experiment is isolated; neither patch is integrated into production by this plan.

On Linux first, the combined candidate passed `cargo fmt --all --check` and the pinned CUDA Sudoku golden and strict-cuDNN TinyStories retained code/ID comparison using `cargo test -p ncm-backend-cuda --release --features cuda-cudnn --test generator_golden --test phase4_fused_norm_probe -- --include-ignored`. Its MLX-only change does not alter CUDA code. The focused log `reports/phase4-fused-rms-cuda-v1.log` has SHA-256 `9f12fa0ca54c6c02664b2fe22f3934faa2009aed1f4e77f813da9be55fc6a445`; this is not a full CUDA gate.

On the Mac, verify source hashes, run the existing focused weighted-versus-broadcast RMS test and compare seed-42 TinyStories output with the retained hybrid candidate. A targeted old/new complete-request screen can determine whether further work is warranted. Any changed sampled outputs require unchanged-reference numerical and quality evaluation. Full CUDA then Metal checks, quality, and three-process Python comparisons remain necessary before integration; a short screen cannot resolve a previously observed tail.
