# TinyStories Metal development observations

These are development observations, not an Apple acceptance gate. The native categorical operation passed a real-Metal boundary/invalid-row test and matched an independent FP64 inverse-CDF calculation for 256 controlled 4096-way rows. A CPU stress test identified 47 errors in three million comparisons for an earlier floating-threshold calculation; that version was replaced. The current integer-threshold comparison passed five million CPU comparisons against a long-double calculation. The checked CPU program is `tools/reference/metal_categorical_threshold.c`. CPU arithmetic is not a substitute for the Metal test.

Using the 16 generated-input development rows from seed 100 and the same pinned Python CUDA teacher trace used in the [CUDA investigation](cuda-numerical-investigation-v1.md), Rust Metal matched all 10,256 codec codes, 2,048 final IDs and 10,240 generator head argmax choices. It nevertheless placed 248 floating values outside the existing accumulated diagnostic band (`atol=5e-4`, `rtol=2e-4`); the worst normalized error was about 4.82. No tolerance was changed. Its summary is `reports/phase4-tinystories-natural-trace-v1/metal-100.json`, SHA-256 `a9597ac773b05698605c52e13ac1c27eac3875be47dbd62ca6f837ef9dfc588e`.

An independently written Python MLX adapter, still under qualification, matched all 2,048 final IDs and 10,240 head argmaxes on the same forced codes. Its 148 generator/final-logit elements outside that band have a similar distribution to Rust's generator/final-logit exceptions. This suggests a common cross-runtime numerical effect but does not establish its cause or prove Rust and Python MLX tensors equivalent. The reference is not a replacement for pinned upstream Python. Its summary is `reports/phase4-tinystories-natural-trace-v1/python-mlx-100.json`, SHA-256 `916a9fad118cb9ebc4c37457746ae57565a99d5b1e89391a357fea341d9671a7`.

One exploratory fresh process per runtime ran five warmups and 30 batch-1 generation/readback trials. Rust's median was 93.827 ms and peak process RSS was 1,150,631,936 bytes; Python MLX's median was 107.560 ms and peak RSS was 1,098,022,912 bytes. Rust's MLX peak/active/cache values were 636,465,716 / 513,888,996 / 612,205,444 bytes; Python's were 638,265,464 / 502,572,276 / 610,896,783 bytes. Rust was faster in this preliminary run but used more process peak RSS, failing the required memory direction. Each implementation uses its own categorical random stream. There was no repeated alternating comparison or activity capture, and the adapter is not yet fully qualified. Raw JSON and `/usr/bin/time -l` files are retained in `reports/phase4-tinystories-natural-trace-v1/`; the Rust/Python JSON SHA-256 values are `75b7396b9c49bb168438229d60093a7d3bb15492c30c292a1db0fd8f0de2a57d` and `fb1110b7d0562b05921c8ce643b2687a12c26ae6892950ee384d7da0e158fa7e`.
