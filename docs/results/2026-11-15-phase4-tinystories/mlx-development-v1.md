# TinyStories Metal development observations

These are development observations, not an Apple acceptance gate. The native categorical operation passed a real-Metal boundary/invalid-row test and matched an independent FP64 inverse-CDF calculation for 256 controlled 4096-way rows. A CPU stress test identified 47 errors in three million comparisons for an earlier floating-threshold calculation; that version was replaced. The current integer-threshold comparison passed five million CPU comparisons against a long-double calculation. The checked CPU program is `tools/reference/metal_categorical_threshold.c`. CPU arithmetic is not a substitute for the Metal test.

Using the 16 generated-input development rows from seed 100 and the same pinned Python CUDA teacher trace used in the [CUDA investigation](cuda-numerical-investigation-v1.md), Rust Metal matched all 10,256 codec codes, 2,048 final IDs and 10,240 generator head argmax choices. It nevertheless placed 248 floating values outside the existing accumulated diagnostic band (`atol=5e-4`, `rtol=2e-4`); the worst normalized error was about 4.82. No tolerance was changed. Its summary is `reports/phase4-tinystories-natural-trace-v1/metal-100.json`, SHA-256 `a9597ac773b05698605c52e13ac1c27eac3875be47dbd62ca6f837ef9dfc588e`.

An independently written Python MLX adapter, still under qualification, matched all 2,048 final IDs and 10,240 head argmaxes on the same forced codes. Its 148 generator/final-logit elements outside that band have a similar distribution to Rust's generator/final-logit exceptions. This suggests a common cross-runtime numerical effect but does not establish its cause or prove Rust and Python MLX tensors equivalent. The reference is not a replacement for pinned upstream Python. Its summary is `reports/phase4-tinystories-natural-trace-v1/python-mlx-100.json`, SHA-256 `916a9fad118cb9ebc4c37457746ae57565a99d5b1e89391a357fea341d9671a7`.

One exploratory fresh process per runtime ran five warmups and 30 batch-1 generation/readback trials. Rust's median was 93.827 ms and peak process RSS was 1,150,631,936 bytes; Python MLX's median was 107.560 ms and peak RSS was 1,098,022,912 bytes. Rust's MLX peak/active/cache values were 636,465,716 / 513,888,996 / 612,205,444 bytes; Python's were 638,265,464 / 502,572,276 / 610,896,783 bytes. Rust was faster in this preliminary run but used more process peak RSS, failing the required memory direction. Each implementation uses its own categorical random stream. There was no repeated alternating comparison or activity capture, and the adapter is not yet fully qualified. Raw JSON and `/usr/bin/time -l` files are retained in `reports/phase4-tinystories-natural-trace-v1/`; the Rust/Python JSON SHA-256 values are `75b7396b9c49bb168438229d60093a7d3bb15492c30c292a1db0fd8f0de2a57d` and `fb1110b7d0562b05921c8ce643b2687a12c26ae6892950ee384d7da0e158fa7e`.

A direct follow-up compared Rust Metal generator tensors against an MLX-adapted trace generated from those same fixed codes. All 11 generator heads and the final decoder logits were within the existing accumulated band; all head argmaxes and final IDs matched. The direct comparison SHA-256 is `3370f0544bcf94fa947c41a7294c6c6f50eaa81e88edd30e25e5fb96b4697b78`; the merged adapted trace SHA-256 is `9cd30b0b42d397e005e4fbe548eb3ce4d842d10a6f306ad02f57069a8c4e6ab4`. This is a 16-row development comparison, not full quality qualification, and it does not erase the cross-runtime exceptions above.

A first attempt to reduce process RSS loaded and validated the full training bundle and dropped it before uploading the model. Its batch-1 Rust peak was 1,150,402,560 bytes and median was 93.713 ms, essentially unchanged from the first development run and still above the retained Python baseline. The subsequent streaming-validation candidate validates the entire training bundle's file hash, tensor metadata and per-tensor hashes without retaining its payload. Its CPU corruption checks and real TinyStories CUDA smoke passed; its Mac RSS and MLX behavior have not yet been measured.

A subsequent safety review identified that invalid categorical rows produce `u32::MAX`, while a later codebook lookup could occur before the final code validation. [MLX documents out-of-bounds indexing as undefined](https://ml-explore.github.io/mlx/build/html/usage/indexing.html). The candidate now bounds indices only for the intermediate embedding and preserves the original sentinel in the returned code sequence, which is checked and rejected before any result is returned. CUDA sentinel and generation tests pass; real-Metal sentinel testing and updated performance remain pending.

The combined sentinel-safe and separate-Q/K/V-view candidate passed real-Metal sentinel and Q/K/V order tests. Its 16-row direct comparison with the Python MLX adapted trace was byte-identical to the previous comparison summary (SHA-256 `3370f0544bcf94fa947c41a7294c6c6f50eaa81e88edd30e25e5fb96b4697b78`); generator tensors remained within the existing accumulated band and all generator argmaxes and final IDs matched. Against the pinned Python CUDA trace, the comparison summary was also byte-identical to the previous one (SHA-256 `a9597ac773b05698605c52e13ac1c27eac3875be47dbd62ca6f837ef9dfc588e`), retaining the documented cross-runtime float-band exceptions.

## Expanded fixed-code comparison

Four further 16-row pinned Python CUDA development traces (seeds 101–104) were compared alongside seed 100. Across 80 rows, Rust Metal matched all 51,280 codec codes, 10,240 final IDs and 51,200 generator head argmaxes. The original CUDA reference comparison had respectively 248, 590, 204, 161 and 338 floating values outside the existing accumulated band: 1,541 of 428,605,440 captured floating values. The worst normalized error was 9.0185 at `generator.level_11.logits`. These observations do not pass or alter the original numerical band.

For each seed, a separate Python MLX adapted trace was also compared on the same forced codes. Every generator head and final logit element remained within the existing band and their decisions matched. The merged adapted trace replaces only the generator tensors; its other tensors are not independent MLX reference evidence. This comparison supports a cross-runtime explanation but does not establish a cause or replace the upstream CUDA reference.

A conservative margin diagnostic counts reference top-two margins no larger than twice the maximum absolute error for the whole corresponding tensor. It flags 76, 153, 93, 135 and 99 generator-head rows respectively, and zero final-logit rows. This bound is deliberately loose; flagged rows did not disagree in this sample and it does not establish future agreement. The diagnostic report `reports/phase4-tinystories-mlx-expanded-v1/near-ties.json` has SHA-256 `7b26c40bdd0fd1cbd45d777b3b700c5923dcf638b150fcda4ca518d25f15dc44`. The per-seed upstream comparison summaries in that directory have SHA-256 values, in seed order: `a9597ac773b05698605c52e13ac1c27eac3875be47dbd62ca6f837ef9dfc588e`, `56fe1adf9d8835166db9136ab08f88a83f3b0a6df2d61a8b8a4babdff7d420cf`, `d85051b52ea1aec003b43b9faea068938359c81324dccd5caa150dcabff54493`, `bb9b652968cc0a6e09f717807c6cf44bbb06410b1d8dafc900b987b080f5e3c2` and `b251b2faf96eebb7458699bd5bac2c721301a7120aee387046461148201c9c51`.
