# Sampled residual reduction-order screen

A CPU-only diagnostic evaluated simple FP32 fused multiply-add reduction orders using the exact captured CUDA residual input, weights, bias and output. The 256 selected coordinates comprise 128 CUDA blended outputs closest to zero and 128 deterministic random coordinates (seed 4217), so this is a targeted, non-representative sample. Kernel-major and channel-major orders, 1/2/4/8/16/32 accumulators, sequential/tree reductions, and bias before/after accumulation were screened. The FP64-based FMA emulation was spot-checked on 1,920 operations against Linux `libm` `fmaf`; that is not proof of equality for every operation.

The best of these sampled orders matched only 20 of 256 CUDA convolution outputs bit for bit; the recorded MLX blend matched 15 of 256 CUDA blends bit for bit. Both that best order and the MLX blend had one sampled output outside the existing diagnostic band. These results do not identify cuDNN's actual reduction schedule, rule out other schedules, establish a numerical gate, or justify a production kernel. They do show that the simple orders tested are not an immediate exact CUDA match. No tolerance changed.

`tools/reference/phase4_residual_reduction_probe.py` checks the pinned artifact, input hashes and exact shared residual input, then fingerprints its inputs and source before/after. Python 3.14.9 / NumPy 2.5.4 syntax check, 1,920 `fmaf` spot checks and the real retained-input execution passed on Linux.
