# Isolated two-by-64 generator experiment

The [batch-64 probe](mlx-batch64-probe-v1.md) left a narrow estimated latency margin for two chunks against Python batch 128, without measuring a combined request. This experiment applies `tools/bench/phase4_generator_hybrid_norm.patch` and then `tools/bench/phase4_generator_chunk64.patch` to an isolated checkout. MLX limits internal TinyStories generation chunks to 64 rows; CUDA keeps the full batch. Generator equations, sentinel checks and original level-major SplitMix64 word assignments are retained, and chunk outputs are concatenated in original row order. Precomputing random words and concatenating tensors add overhead and memory; changed matrix shapes can alter FP32 rounding or sampling decisions. This is not a proven performance fix.

The focused Rust test `chunked_generation_retains_level_major_random_words` passed for batches 1, 64, 65, 127 and 128, verifying original stream order and chunk row slices. Formatting and `cargo check -p ncm-model` passed. On Linux, the pinned CUDA Sudoku golden and strict-cuDNN TinyStories retained code/ID comparison passed using `cargo test -p ncm-backend-cuda --release --features cuda-cudnn --test generator_golden --test phase4_fused_norm_probe -- --include-ignored`; `reports/phase4-chunk64-cuda-v1.log` SHA-256 is `e52c33a9c615f21ddcf235f40acaeac0b5922e8019f8562813dc0b7dc62cb768`. The CUDA path is unsplit, and these focused checks do not replace its full gate.

Next compare real Metal chunked samples against the retained hybrid outputs, including the 64/65 and 127/128 boundaries. If the result is promising, time complete batch-128 requests including output concatenation and compare memory under the same cache and lifecycle policy. Any numerical differences require explicit unchanged-reference and quality evaluation; neither the RNG test nor CUDA outputs prove Metal equivalence. Full CUDA then Metal validation and a paired Python comparison remain required before integration.
