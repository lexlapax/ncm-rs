# Hybrid generator batch-64 probe

A single fresh process of the existing hybrid MLX lifecycle binary ran batch 64 with the same explicit 4,096 MiB cache, five warmups, 30 generation/readback trials, output drop and GPU barrier used in the batch-128 comparisons. Median, p95 and maximum were 1066.47, 1086.84 and 1117.82 ms; peak process RSS was 1020.61 MiB, and MLX peak / active / cache were 2458.92 / 477.63 / 4070.41 MiB.

Twice the measured median is 2132.93 ms, compared with the earlier three-process Python batch-128 median of 2224.69 ms and the earlier hybrid Rust batch-128 median of 2553.30 ms. These are separate runs with different system conditions. Doubling one median is only a rough lower-order estimate: a real split needs to preserve per-row random-word assignment, concatenate results, and account for extra memory and overhead; it may change floating-point results and does not prove that the tail is avoided. No split implementation or performance pass is claimed.

The process, input artifacts, native MLX libraries and candidate generator source were fingerprinted before and after and matched. CPU process snapshots were taken before and after, not continuously; GPU activity and exclusive reservation were unavailable.
