# Request-aligned Metal activity diagnostic

The isolated [timestamped lifecycle diagnostic](mlx-wall-gpu-diagnostic-plan-v1.md) ran at batch 128 with the same 4,096 MiB process-local cache, output drop and GPU barrier policy as the unmarked hybrid benchmark. One fresh marked process ran first, followed by one unmarked process; each had five warmups and 30 measured requests. The optional CPU and system-wide GPU observers ran throughout. Instrumentation can perturb execution, so these are diagnostic observations, not a Python comparison or a performance gate.

The marked process had median / p95 / maximum request times of 1969.05 / 2014.39 / 2019.11 ms; the unmarked process had 1974.08 / 2020.40 / 2028.97 ms. Neither had a request above four seconds. Thus this capture does **not** contain the earlier long-tail event and cannot explain or resolve it. All 35 marked request timestamp triples were ordered, and the 30 measured wall durations agreed with monotonic durations within 0.0078 ms. The previously declared 20 ms check is a diagnostic clock-consistency bound, not a model tolerance.

The observer recorded 69 GPU snapshots over both processes. Twenty-nine of the 30 measured marked requests had one snapshot; one had none. The 29 associated system-wide reported device-utilization values were 94–95%; 28 last-submitter snapshots matched the marked process PID and one did not. These counters have an uncalibrated averaging window and do not measure target-process GPU time or prove causation. The median marked request time to the sampler-return marker was 1897.23 ms; this includes work and readback inside the sampler. The prior [slow comparison](generator-hybrid-norm-mlx-large-performance-v1.md) remains a failure.

Both observer threads reported no errors and watched inputs and sources remained stable.
