# Batch-sensitive normalization: initial Metal screen

The isolated [candidate](generator-hybrid-norm-plan-v1.md) uses the original composed generator normalization below batch 16 and the previously studied fused hook at batch 16 and above. On Linux it passed the pinned Sudoku CUDA golden and strict-cuDNN 128-row TinyStories output check. On Metal, single-batch seed-42 outputs at batches 1, 4 and 15 matched the original implementation; batches 16 and 128 matched the fused candidate in codes, raw IDs, decoded text and re-encoded tokens. Both comparison binaries also matched the first 128 rows of their corresponding retained batch-128 captures. The branch manifest (`reports/phase4-hybrid-norm-mlx-branches-v1/manifest.json`) has SHA-256 `6cba8679f29b3fc01d01e5055438bb7673bf2a51b063524005e581d0b4f26c44`, verified against the Mac; watched inputs and binaries were stable. This is limited identity evidence, not exhaustive parity.

The hybrid's batch-16 forced-code comparison with the same-device Python MLX adaptation was byte-identical to the earlier fused summary (SHA-256 `66c311cc68ab2c1ea18f858b6470913070f9a31a21d05c31c6a6c882d59b3218`). The larger-branch implementation is the same candidate that passed the [nonblind quality retest](generator-fused-norm-quality-v1.md), but this screen does not independently establish that every official-seed hybrid sample is identical. The original CUDA cross-runtime float-band exception remains unchanged.

A targeted comparison ran three alternating fresh processes per runtime at batches 1 and 4, each with five warmups and 30 measured generation/readback requests. Rust used the hybrid binary, dropped outputs and evaluated a GPU barrier inside timing, with an explicit process-local 512 MiB MLX cache limit. Python used the separately qualified MLX adaptation and its default cache. Rust and Python use different random streams.

| Batch | Python / Rust median ms | Python / Rust pooled p95 ms | Python / Rust peak RSS MiB | Python / Rust MLX peak / active / cache MiB |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 107.58 / 94.21 | 107.93 / 94.68 | 1046.52 / 1024.78 | 608.70 / 479.29 / 579.24; 607.37 / 477.63 / 512.61 |
| 4 | 170.24 / 143.04 | 171.97 / 144.05 | 1046.55 / 1025.83 | 975.69 / 479.29 / 2401.80; 971.17 / 477.63 / 512.70 |

Rust was faster and lower in each listed memory counter in this small-batch run, although the MLX peak margins are only 1.33 and 4.52 MiB. RSS is a whole-process high-water mark, and MLX counters have different scopes; the cache limit is not an instantaneous hard bound. Thirty-one approximately two-second CPU activity samples were captured, without direct GPU activity or exclusive reservation. No clock/power setting changed.

These results do not resolve the [batch-128 tail failure](generator-fused-norm-mlx-performance-v1.md), establish a combined four-batch gate or validate long-lived multi-model use. Full CUDA-then-Metal checks, verified official-seed output identity or scoring, and repeated performance evidence for the final hybrid remain required before integration. Raw summaries are in `reports/phase4-hybrid-norm-mlx-small-bench-v1/`; the summary, manifest and activity SHA-256 values are `ba6e639e9494811b8006707fd3f2c9cb7b85946b0a246a80157db9a4dba11c2b`, `3d41d5a26bf314db374e15f07804816fbf7f13b2fdf5fedb57e5f3e08d529f6d` and `9d489e1e1ddf6b9ed18e9626840a798ce1aefff9b2443f8d05959976921fc313`, respectively, verified against Mac originals.
