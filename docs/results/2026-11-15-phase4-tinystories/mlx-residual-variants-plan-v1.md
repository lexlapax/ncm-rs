# Equivalent MLX residual-convolution screen

The first reconstruction residual convolution is an early CUDA/MLX divergence on the same captured input. A [sampled FP32 reduction screen](residual-reduction-screen-v1.md) did not find a simple bit-identical CUDA order; a [full FP64 comparison](mlx-residual-fp64-v1.md) shows that exact arithmetic alone would not ensure CUDA-band agreement.

`tools/reference/phase4_mlx_residual_variants.py` prepares a limited real-Metal screen of the existing 1D convolution, the same one-dimensional equation expressed as a height-one 2D convolution, and a sum of three kernel-position matrix multiplies. Each receives the same 128-row CUDA-captured residual input and pinned weights, compares its convolution and blended output with the CUDA trace using the unchanged diagnostic band, and captures the blended result for possible FP64 assessment. Three warmups and five synchronized calls give only an operator-level screening time; this is not an end-to-end benchmark, memory gate or quality result. Source, artifact and reference are fingerprinted before/after; no production behavior changes.

Python syntax check passed; real-Metal numerical and timing results are recorded in the subsequent screen. A promising formulation would require full model correctness, quality, memory and platform validation. If none reduces the discrepancy without unacceptable cost, retain the existing implementation and evidence.

After the [16-row Rust full-model regression](mlx-first-residual-three-gemm-screen-v1.md), the screen gained an explicit `--batch 16` option to compare the first 16 rows of the same retained 128-row CUDA input/output capture with MLX dispatched at batch 16. The CUDA reference remains the captured batch-128 output, so this isolates the effect of MLX dispatch shape relative to fixed reference values; it is not a fresh batch-16 CUDA oracle. Python syntax check passed; real-Metal results are recorded in the subsequent screen and follow-up.

The 16-row Metal screen reports 1,940 blended outside-band values for the standard convolution and 1,294 for three matrix multiplies; the corresponding first 16 outputs from the batch-128 capture produce the same counts. This does not explain the full-model regression. `tools/bench/phase4_mlx_first_residual_probe.rs` prepares a direct same-input Rust candidate capture for comparison with the Python MLX result. It runs only in the isolated rejected candidate and is not production code.

The [follow-up](mlx-first-residual-shape-investigation-v1.md) completed the direct Rust comparison and records its limitations.
