# Restricted XSum top-1 generation on CUDA

The pinned XSum configuration uses temperature 1, top-k 1, top-p 0 and CFG 0. With a unique finite maximum, the upstream code's top-k filtering leaves one choice per head. The new generation path selects that choice on CUDA, uses the existing model and reconstruction operations, and applies the pinned sequential FP64 output penalties explicitly on the CPU. Output logits are read back at most four batch rows at a time to bound host workspace; their device allocation remains. The path has not yet been benchmarked, exposed in the CLI or qualified for task quality.

The upstream sampler sorts even tied maxima. A small exploratory set of 64 artificial tie rows (`reports/phase4-xsum-selection-screen-v1/ties.py`, fixed generator seed 371, sampling seed 42) produced 48 CPU choices different from first-index argmax and none on this CUDA device. This does not characterize every tie or imply CPU and GPU sort rules. To avoid silently substituting a different result, the CUDA selector returns a sentinel for exact maximum ties or any nonfinite logit; generation checks it and fails explicitly. A safe embedding prevents out-of-range indexing before the sentinel check. The native path does not reproduce or consume PyTorch's random stream, and unsupported sampling parameters and CFG are not implemented.

On two synthetic prefixes with 24 and 497 non-padding positions, actual pinned Python CUDA generation and Rust strict-cuDNN generation agreed on all 400 code choices and all 96 penalized output IDs; all 96 raw greedy IDs also agreed. All 6,799,360 captured floating values were inside the unchanged `atol=5e-4, rtol=2e-4` accumulated diagnostic band. This is limited correctness evidence and does not establish quality or general numerical parity. A focused real-CUDA kernel test covers finite unique maxima, within-thread and cross-thread ties, NaN, both infinities, invalid shapes and replacement of lower ties by a later unique maximum. CPU tests show independent row chunks produce the same penalty selections as a single batch.
