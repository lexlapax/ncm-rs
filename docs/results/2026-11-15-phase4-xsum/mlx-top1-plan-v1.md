# XSum Metal top-1 preparation

The fixed-code [Metal teacher comparison](mlx-teacher-v1.md) passed, but generated-code selection was unsupported. This candidate adds an explicit row-contiguous Metal top-1 kernel for 4,096 logits per position. For the earlier artifact profile it rejects exact maximum ties; for the rotary reference profile it chooses the lowest index, matching the pinned CUDA reference ordering. Both modes return the existing invalid sentinel for any nonfinite input. A real-Metal regression test covers unique maxima, ties including signed zero, NaN/infinities and invalid shapes. These are explicit backend implementations, not a CPU fallback.

The accompanying initial generation probe compares two Metal-generated sequences from synthetic padded prefixes and every captured level with the retained pinned-Python CUDA trace from `reports/phase4-xsum-top1-bound-v2/reference/trace.safetensors` (SHA-256 `3064634953718a9424aba74d83edd4607774e4a110da3c969abd7f765b9f27e3`). It uses the existing explicitly invoked CPU FP64 final-token penalty selector because Metal does not provide device FP64; its memory and speed cost must be measured. It preserves the existing accumulated floating-point band and prints results before failing any band or decision mismatch. The reference trace was copied to a new Mac results directory and hash-verified. Linux full CUDA checks precede Mac compilation and tests.

This is a bounded top-1 candidate, not a CLI implementation, full task-quality result, positive-CFG or stochastic qualification, or an MLX performance/memory pass. The XSum reference-profile choice on Metal must be tested explicitly; the claimed ordering is scoped to matching the pinned CUDA reference, not a guarantee about general MLX or PyTorch tie behavior.
