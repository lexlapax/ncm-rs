# XSum generator host preflight

`XsumGeneratorInspection` checks the pinned XSum generator configuration using a strict typed schema, verifies the 192 FP32 parameter tensors and nine finite positive head temperatures, validates the two persistent level and block-attention buffers against the exact nine-level geometry, and validates the 50,304-element FP32 token allowance. It performs no backend allocation and does not construct or execute a generator. The local pinned v2 XSum artifact passed this preflight via the explicitly run ignored `real_xsum_generator_inventory_and_allowance_preflight` test. Synthetic tests reject changed/duplicate/unknown model fields and corrupted level or attention buffers. `ncm-model` focused tests, formatting and Clippy passed.

The first `RUSTC_WRAPPER= tools/check.sh` run failed in the separate CPU-only `test_real_writers_and_owned_process_samples_compose` fixture after an `ObservationMismatch` for one child; its retained log SHA-256 is `da939776c4c3464ed120f180ab933c103a7676de2befda79c08d6eb03cb851d2`. The exact mismatch reason was not retained in that fixture's failure output. The unchanged test passed independently, and an unchanged full rerun passed all local checks, including 495 report-tool tests; `reports/phase4-xsum-generator-preflight-check-v2.log` SHA-256 is `f5c15b67c1b76d0e7e6cc0776685bb6d978747ca3f81429761c7c932591f4bbd`. The earlier failure is not erased or attributed to the new model code. Neither check adds XSum generator execution, GPU correctness, quality, memory or performance evidence.
