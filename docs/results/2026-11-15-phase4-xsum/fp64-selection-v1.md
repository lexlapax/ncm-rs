# XSum FP64 output-token selection

`select_xsum_tokens_cpu` implements the official XSum evaluator's fixed final-token adjustments in native Rust on explicitly supplied FP32 logits and token allowance, promoting each to FP64 before applying upstream's frequency, deficit and four-step adjacency operations in the same sequence. It maintains one count per vocabulary entry and only a per-request allowance/count workspace rather than an FP64 copy of the full logits. It returns raw IDs before EOS cutting and text decoding; invalid shapes, nonfinite logits or invalid allowance values fail explicitly. This CPU function is an explicit implementation, not an automatic device fallback, and is not yet connected to the model or CLI.

The small [oracle fixture](../../../tests/fixtures/xsum-penalty-oracle-v2.json) was produced by `tools/reference/xsum_penalty_fixture.py`, which verifies the pinned upstream revision and `scripts/eval_shard.py` hash and executes that exact `pick_tokens` function on identical CPU and CUDA inputs. The fixture uses PyTorch `2.15.0+cu132` on an NVIDIA RTX 3060 Ti and requires the CPU and CUDA raw IDs to match. It covers varied values, equal-logit/equal-allowance ties, and repeated recent tokens; the Rust integration test matches every captured ID. Rust unit tests also cover independent batches, ties and invalid inputs. Fixture SHA-256 is `b33ef40267ec231a5af8f1bbce1fa2f4a3773d32c687902abb31b54c974a2dc4`; fixture generator SHA-256 is `b6a79ac6af15897d90b53a7bade840768bb5415ebb85c3fd8624444d76513936`.

Focused `ncm-model` unit and oracle tests, formatting and Clippy pass. `RUSTC_WRAPPER= tools/check.sh` also passes the default local suite, including 495 report-tool tests; `reports/phase4-xsum-fp64-selection-check-v1.log` SHA-256 is `7ddf4a4875c54932048807a2c82d5a7b11b63694fa914b38d4aabb153fec1e27`. This is a bounded synthetic oracle comparison, not the XSum CUDA gate, full-profile numerical or quality evidence, or a performance/memory result. Readback and CPU selection may be expensive at the official batch and vocabulary sizes and must be measured against Python after integration. The generator, prefix masks, tied heads, model artifact semantics, EOS policy and MLX validation remain outstanding.
