# XSum fixed-code teacher comparison on CUDA

The XSum teacher path takes a 512-token padded prefix and fixed code IDs at each of the nine levels. It uses the checkpoint's query-level-zero state, prefix padding mask and tied codebooks, then reconstructs decoder logits. It does not sample codes, implement classifier-free guidance or apply output penalties itself, and is not wired into the CLI.

The pinned Python CUDA reference and strict-cuDNN Rust probe compared two synthetic rows, with 24 and 497 non-padding prefix tokens and 200 forced codes per row. All 6,799,360 compared floating-point values were inside the existing accumulated diagnostic band `atol=5e-4, rtol=2e-4`. All 400 level-head argmax choices, 96 raw greedy output IDs and 96 IDs after the separate explicit CPU FP64 XSum selector agreed. This is a limited same-device fixed-input comparison; it does not establish stochastic behavior, end-to-end task quality or performance. No tolerance or upstream algorithm was changed.

The Python capture is `tools/reference/xsum_teacher_trace.py`; it checks the upstream revision and checkpoint hashes and invokes the pinned upstream generator with controlled code selections. The Rust comparator is `crates/ncm-backend-cuda/examples/xsum_teacher_probe.rs`; it prints per-tensor statistics and returns an error for an incomplete trace, any outside-band value or decision difference.

A source-bound replay is retained at `reports/phase4-xsum-teacher-bound-v1/`. It ran the reference with `--upstream .reference/upstream-ncm --source artifacts/upstream/xsum-phase4` and the probe with `artifacts/canonical/xsum-phase4-v2` and the reference safetensors.
