# XSum CUDA FP64 output selection

An explicitly selected CUDA backend path now performs the pinned sequential XSum output penalties on device. For every output position it computes FP64 frequency and deficit adjustments, applies the previous four adjacency penalties in order, and reduces scores with first-index tie handling. The CUDA implementation uses explicitly rounded FP64 operations and propagates invalid inputs through a sentinel; the model rejects the sentinel. It does not silently fall back on another backend. The prior explicit CPU FP64 path remains available. The untraced device generation path skips calculating a separate raw-greedy output that XSum does not use; traced execution still captures it. Fully unpadded batches reuse the existing additive attention mask rather than adding an all-zero padding mask.

Real-CUDA tests match the pinned upstream oracle's varied, tie and repeated-history fixtures and CPU results for ten additional vocabulary sizes around reduction-tile boundaries. They also reject invalid shapes and detect nonfinite values and negative allowance, including an invalid value after the first output position. Full-model diagnostics match the pinned Python CUDA reference for two different padded synthetic prefixes, two real passages and a separate two-row full-prefix case. In each comparison all 400 generated codes and all 96 penalized IDs match, and the captured values remain inside the unchanged diagnostic band. The untraced path matches the traced path in codes and IDs. These limited comparisons do not establish quality across the dataset.
