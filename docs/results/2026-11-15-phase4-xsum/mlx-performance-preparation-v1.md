# XSum Metal performance comparison preparation

The [32-passage Metal top-1 CLI comparison](mlx-cli-real-v1.md) passed, while the later seeded sampler candidate has [remaining exact cross-device differences](mlx-fixedpoint-candidate-v1.md). Before a full performance gate, this preparation adds an independent Python MLX XSum top-1 adaptation and a short native Rust screen. The adaptation loads only the pinned rotary artifact, follows the upstream padded-prefix/query-level-zero, tied-codebook, cascade and decoder structure, and explicitly applies the upstream final-token penalties in NumPy FP64 because Metal has no FP64 tensor arithmetic. It is an adapted same-device comparison, not the original PyTorch implementation or a qualified oracle.

The NumPy penalty selector was compared with the AST-extracted pinned upstream `pick_tokens` function on repeat-heavy and tied inputs and passed (`tools/reference/test_xsum_numpy_selection.py`); nonfinite input is rejected. The adapter and its qualification runner passed Python syntax checks. On Mac, first compare all 6,400 codes and 1,536 IDs for the retained 32 real passages against the pinned Python CUDA reference. A mismatch remains a failed adaptation qualification and must be investigated, not silently accepted. The short Rust example uses two warmups and five trials per process for batches 1, 4 and 32, with either top-1 or a seeded stochastic request, and records MLX active/peak/cache memory. A corresponding Python top-1 screen is meaningful only after adapter qualification. These short screens are diagnostic; the project performance gate requires longer alternating fresh-process runs, RSS, activity and device-memory scopes.

The first Linux `tools/check.sh --cuda` attempt (`reports/phase4-xsum-mlx-perf-screen-linux-v1.log`) stopped in an unrelated process-observer fixture after reporting an unexpected live executable identity. The affected test passed in isolation (`reports/phase4-xsum-mlx-perf-screen-linux-isolated-v1.log`); the complete rerun passed, including 18 real-CUDA operator cases (`reports/phase4-xsum-mlx-perf-screen-linux-v2.log`). Mac-only adapter and benchmark execution remain pending.
