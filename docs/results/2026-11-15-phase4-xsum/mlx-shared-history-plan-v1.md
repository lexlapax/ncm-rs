# XSum 32-passage shared-history diagnostic

The original [Metal seeded comparison](mlx-stochastic-real-v1.md) had its first code differences at flattened positions `(row, position)` of `(0,27)`, `(7,15)`, `(14,2)` and `(25,144)`. The separate eight-passage [diagnostics](mlx-stochastic-diagnostic-v1.md) found both a same-logit sampler difference and forced-history model-logit effects but cannot establish the cause of these four specific divergences.

A strict-CUDA example now runs the saved seed-42 CUDA code histories for all 32 original prefixes and captures the nine level-head tensors. Its 104,858,504-byte result is `reports/phase4-xsum-shared-history-cuda-v1/logits.safetensors`, SHA-256 `c57f4f6c9a88e0f4d247dc7bc6fa6cb525e3c87945205fa33b0535af2de74018`; its input and seeded output hashes are documented in the [seeded plan](mlx-stochastic-plan-v1.md). The file was copied to a new Mac results directory and hash-verified.

The Metal probe forces the same saved CUDA histories, compares level logits under the existing accumulated band and FP64-softmax total variation, and samples both the saved CUDA logits and Metal logits using the same SplitMix64 words. It reports every choice difference and explicitly records the four first-difference positions. This distinguishes same-logit sampler behavior from forced-history backend effects at those observed positions; matching forced histories do not prove later freely generated histories match. Run after Linux CUDA validation, retain all findings, and do not treat the diagnostic alone as a quality or performance gate.
