# XSum Metal CLI: 32 real passages

At commit `b907bf6`, the release Metal CLI using the rotary reference artifact produced all 6,400 generator codes and 1,536 final IDs exactly matching the retained pinned Python CUDA output on 32 real XSum passages. The [source-bound result](mlx-cli-real-v1.json) has SHA-256 `ae64a585df3eef7234f1670a14836974405de0ac5c96cc8d7069f6c3c8231377`; CLI output SHA-256 is `30b684ab76049072a0750c53b792d88abf9c711a41df287888437d79073350d2`. The same check confirmed that positive CFG and seeded stochastic requests fail explicitly on Metal. The CLI uses Metal model execution and explicitly performs the upstream final FP64 token penalties on the CPU.

Linux full `tools/check.sh --cuda` passed first, with 18 GPU operator cases; strict-cuDNN tie and traced/untraced regressions and strict CLI lint also passed. The cached CUDA PTX failure and correction are documented in the [plan](mlx-cli-plan-v1.md). On Mac, `cargo build --release --locked -p ncm-cli --features mlx` succeeded, followed by `python3 tools/bench/check_xsum_mlx_cli.py --binary target/release/ncm --inputs reports/phase4-xsum-mlx-cli-inputs-v1/prefixes.json --reference reports/phase4-xsum-mlx-cli-inputs-v1/reference.json --output reports/phase4-xsum-mlx-cli-real-v1`. The raw result and outputs are retained on Mac under that output directory and locally under `reports/phase4-xsum-mlx-cli-captured-v1/`.

This is one fixed batch, not full XSum task quality or a performance/memory measurement. Positive CFG and stochastic generation remain unsupported on Metal. Real-device regression, larger output/quality comparison and repeated speed/memory measurements remain required.
