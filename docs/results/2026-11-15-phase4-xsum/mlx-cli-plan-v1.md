# XSum Metal CLI and real-passage comparison plan

The initial Metal top-1 selector and synthetic generation trace [passed](mlx-top1-v1.md). This change exposes the official temperature-1/top-k-1/top-p-0/CFG-0 XSum path through `ncm sample-xsum ARTIFACT mlx INPUT_JSON`. The shared model now offers an explicit untraced CPU-FP64 final selector, preserving the existing sequential upstream penalty arithmetic and bounded readback while omitting unused traced greedy output. The CLI rejects positive CFG and seeded stochastic mode on Metal until separately implemented and validated; it never switches backend silently. CUDA's existing modes remain available.

The retained strict-CUDA top-1 probe now compares the new untraced CPU-final path with the existing traced path and pinned Python. It passed for the earlier and rotary reference profiles. An initial `cargo check` lacked `CUDA_COMPUTE_CAP` and failed; the corrected check passed but reported an unused import, which was removed. The first rotary-profile run and strict tie regression then failed: an older cached CUDA PTX lacked the reference tie kernel. Rebuilding the Rust backend alone exposed `CUDA_ERROR_NOT_FOUND`; regenerating `generator_layout.cu`'s output by updating its source timestamp made the strict tie regression and rebuilt rotary probe pass. Prior failing logs are `reports/phase4-xsum-mlx-cli-cuda-{tie-v1,tie-v2,probe-v1}.log`, and the successful test/probe are `reports/phase4-xsum-mlx-cli-cuda-tie-v3.log` and `reports/phase4-xsum-mlx-cli-cuda-probe-v3.json`. `tools/check.sh --cuda` tests the default CUDA feature, not the strict-cuDNN tie case, so the latter was run separately. Previously retained benchmark binaries with the kernel and prior results remain unchanged; the stale local CLI executable must be rebuilt before reuse.

After full Linux CUDA validation, build the reviewed pushed CLI on Mac and compare its output on 32 real XSum passages with the retained pinned Python CUDA batch using `tools/bench/check_xsum_mlx_cli.py`. It verifies the artifact, input and reference hashes, records source and binary hashes, checks all code and ID shapes/differences, and confirms positive-CFG and stochastic CLI requests fail explicitly. A new Mac directory contains the input and Python reference with matching hashes. This single comparison does not establish full task quality, stochastic support, performance or memory; those remain separate gates.

The updated Linux full suite subsequently passed (`reports/phase4-xsum-mlx-cli-linux-v1.log`, 18 real CUDA operator cases); strict-cuDNN CLI Clippy passed with warnings denied (`reports/phase4-xsum-mlx-cli-clippy-v1.log`). After regeneration and release rebuild, the strict-CUDA rotary CLI matched all codes and IDs for the retained 32 real-passage Python reference (`reports/phase4-xsum-mlx-cli-cuda-real-v1.json`). These Linux checks do not compile or establish the Mac-only CLI branch.
