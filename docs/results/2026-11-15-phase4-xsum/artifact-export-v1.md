# XSum pinned artifact export and tokenizer check

`tools/reference/xsum_artifact.py` exports only the pinned XSum source files listed in [the Phase 4 contract](../../PHASE4-TEXT.md), using `torch.load(weights_only=True, mmap=True)` and bit-exact safetensors roundtrips. It preserves 194 generator tensors, 53 codec inference tensors, 27 separately stored EMA/count/hit tensors, and the FP32 50,304-entry `token_unigram` used by upstream final-token penalties. It rejects unexpected inventory counts, aliases, dtypes, nonfinite/negative/non-normalized allowance distributions, source hashes and unpinned GPT-2 tokenizer assets. The artifact contains the pinned tokenizer manifest, payload and license notice; no weights or tokenizer data are committed.

The export command used the pinned `artifacts/upstream/xsum-phase4` files, `artifacts/canonical/tokenizers-qualified/gpt2`, and fresh output `artifacts/canonical/xsum-phase4-v2`. Its manifest SHA-256 is `5df37749e64418c586472a4678600603992357b9bc5e3611da307918e13b237e`; declared payloads total 657,772,935 bytes. The exporter and shared helper hashes match their provenance, and the export report `reports/phase4-xsum-export-v2.json` SHA-256 is `691f78133936e1e6b56864b31c55f9740c5c7b8f020cce824523576abede051c`. An initial attempt correctly rejected an older GPT-2 manifest whose hash differed from the lock. A subsequent preliminary export omitted the tokenizer license required by the embedded tokenizer API; it was superseded by v2 and the generated v1 directory was removed after its manifest was verified. Its earlier report remains under `reports/phase4-xsum-export-v1.json`.

The separate `xsum-inference-v1` loader profile enforces an exact nine-file/four-bundle inventory and explicit 384 MiB per-file and 640 MiB total payload bounds; the other profiles' budgets are unchanged. `cargo test -p ncm-io --locked` passed 13 unit/integration cases, including synthetic inventory/budget and training-stream checks. The release CLI's `inspect` validated the actual complete v2 artifact; `reports/phase4-xsum-rust-inspect-v2.json` SHA-256 is `7cabc3bb05ad8b44b9f3bf98040ab8a63f6750f206e3a451ee48ef856636ab5e`. The embedded Rust GPT-2 tokenizer passed all 89 pinned encode cases and 260 decode cases plus a modified-license rejection using `NCM_XSUM_ARTIFACT=... cargo test --release -p ncm-tokenizers --test embedded_assets xsum_embedded_gpt2_matches_pinned_tokenizer_fixture -- --ignored`. Focused Python XSum and existing TinyStories exporter checks passed (five tests). `RUSTC_WRAPPER= tools/check.sh` passed the default local suite, including 495 report-tool tests; its log `reports/phase4-xsum-artifact-check-v1.log` SHA-256 is `2a9bcadd3bb7a37eb730009f33c36155efb20be664692eb736dfe9711774e1d0`. This check did not run CUDA.

This validates file integrity relative to the manifest and the pinned embedded tokenizer, not authenticity of an arbitrary manifest, XSum model semantics, inference, GPU correctness, quality, performance, or release readiness. The codec and generator still reject this task; Linux/CUDA implementation and full preceding regression checks come next, followed by MLX only after the Linux gate.
