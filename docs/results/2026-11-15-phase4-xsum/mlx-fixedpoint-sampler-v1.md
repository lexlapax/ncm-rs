# Isolated XSum Metal fixed-point sampler result

The [isolated fixed-point experiment](mlx-fixedpoint-sampler-plan-v1.md) ran at commit `d01fbb3` on the saved 32-passage CUDA logits and words. It differed from the original freely generated CUDA choices once in 6,400 draws, versus five differences for the previous Metal sampler on those same logits. The [result](mlx-fixedpoint-sampler-v1.json) has SHA-256 `d93238f12ede0ac2a9535c6e9bb8c651f9bc3cf829f49f863ae0aeeec146e2ec`. Production sampling was not changed.

A subsequent strict-CUDA resampling of the saved logits reproduced all 6,400 original CUDA choices (`reports/phase4-xsum-shared-history-cuda-v1/sampler-result.json`, SHA-256 `39596a871e109edc652f3c22279904db7eeec4269b2a2548f2fcf8d867a7e88f`), so this fixture does not show a forced-trace choice change on CUDA. An independent NumPy FP64 inverse-CDF calculation on the same saved logits and words found zero differences for the experimental fixed-point sampler, four for the previous Metal sampler and one for CUDA. The [source-bound FP64 comparison](mlx-fixedpoint-fp64-v1.json), SHA-256 `1e8b599a401168f5ec7f8224f102dc18d1ce03a48d7fe12f7e763ae04924d167`, is reproducible with `tools/reference/xsum_shared_sampler_fp64.py`. At the remaining CUDA-versus-fixed-point position (row 25, flattened position 144), the fixed-point Metal result agrees with this FP64 calculation. This is a fixture-specific numerical observation, not a claim that either implementation is universally exact.

The experiment retains FP32 exponentials and truncates fixed-point weights below `2^-48`, so boundary and tiny-probability behavior require explicit qualification. It has not been used for full-model generation or benchmarked, and the [original Metal comparison failure](mlx-stochastic-real-v1.md) remains. Linux `tools/check.sh --cuda` passed before the Metal experiment, and strict-CUDA resampling Clippy passed. Candidate production integration should be limited to XSum, preserve existing TinyStories sampling, and require boundary tests, Linux then Metal validation, generated-output quality and speed/memory measurements.
