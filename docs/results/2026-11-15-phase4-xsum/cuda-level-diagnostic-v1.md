# XSum level timing diagnostic

The batch-4 speed gap in the [repeated comparison](cuda-device-selection-v1.md) motivated an instrumented inspection of the first four pinned passages. Two warmups and five diagnostic runs were made once per runtime. Both runs generated the same 800 codes and 192 final IDs. These observations are not acceptance timings.

The first diagnostic synchronized the device at each of the nine head outputs. It showed Rust 5.9–7.7 ms slower per interval, but that instrumentation perturbed runtime scheduling and its summed intervals were inconsistent with the uninstrumented comparison. It is retained as `rust-sync.json` and `python-sync.json`; it cannot isolate the original performance gap.

A follow-up recorded GPU events at the same points without per-level synchronization. Median Rust/Python event intervals in milliseconds were: 71.64/71.16, 72.71/72.57, 73.63/72.93, 73.78/73.30, 75.38/74.58, 76.14/75.40, 76.74/75.98, 78.99/77.97 and 79.85/79.07. The median sums were 679.21/672.70 ms. The measured difference is spread across levels in this instrumented run; it does not identify a single expensive operation or establish the cause. GPU events include any stream idle time between launches. The Rust diagnostic uses traced generation, which performs the raw-greedy diagnostic output later in the request; the level intervals end before that output. The Python and Rust sampling implementations have different internal operations, and the one-process sample is not a controlled estimate of their small production gap.

The Rust diagnostic was built as a local, isolated Cargo package under `reports/phase4-xsum-level-profile-v1/` with the root release settings. Its dependency lock matches the root lock for every package used; the workspace's tokenizer patch was not used by this diagnostic's dependency graph. The event source/binary/artifact fingerprint manifest SHA-256 is `a17cd4d3e38bd8e137edf0e6158d49665bcc6a4524d7c7f1b0c8a4e7c2459c01`; external dependencies and native runtime library bytes were not separately fingerprinted. Rust and Python event result SHA-256 values are `14837ba5078c6bf9deee6cd78b01cd7686bb0df4e832f2c852fddd30421845e3` and `172a5b3454e61090e1808ca2530c780fc675b6f251215b921d3910b6577daf0c`. There was no continuous activity monitor for this diagnostic, and no timing or parity conclusion beyond these inputs is implied.
