# XSum four-position first cascade on CUDA

The pinned XSum codec starts at four concepts and reconstructs 48 positions. Its upstream learned cascade factors the total stride 12 into downsampling strides `[4, 3]` and upsampling strides `[3, 4]`, with eight-group normalization between stages and after the final downsampling stage. The explicit XSum codec validator now checks its exact dimensions, nine level lengths and normalization flags. Shared cascade geometry uses `context_length / first_level`, and the upsampling input check uses that first level. Sudoku and TinyStories retain their existing one-position first-level validation and geometry.

`tools/reference/xsum_cascade_trace.py` captured the pinned Python CUDA codec on two deterministic four-code inputs and a separate deterministic two-row downsampling input. The Rust `xsum_cascade_probe`, using the separately selected strict-cuDNN backend and the pinned v2 XSum artifact, matched the input embedding and downsampling input exactly. Across the final upsampling output, first refinement and final downsampling output, every value was inside the unchanged component band `atol=1e-4, rtol=2e-4`. Their maximum absolute differences were `9.537e-7`, `1.073e-6`, and `1.192e-6`, respectively. This is a small deterministic component comparison, not teacher-forced codec/generator parity, end-to-end quality or performance evidence.
