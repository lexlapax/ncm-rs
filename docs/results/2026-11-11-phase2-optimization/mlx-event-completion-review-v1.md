# MLX event completion and active-memory observations

The installed native library reports MLX 0.32.2. Reviewing the corresponding upstream tag narrows the synchronization question, without proving the wheel's exact source identity or attributing a particular allocation:

1. [Synchronous `eval`](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/transforms.cpp) waits on a synchronizer array. The array's [`wait`](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/array.cpp) waits on its event when needed.
2. The Metal [event implementation](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/event.cpp) waits for a shared-event value. [Encoding the event](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/device.cpp) adds a signal command to the command buffer.
3. The [Metal evaluator](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/eval.cpp) retains input-buffer references in completion handlers. A GPU event becoming visible and all host completion handlers returning are distinct events, so an event wait alone does not establish that those references have already been released. This supports, but does not prove, the pending-cleanup explanation for the observed immediate allocation difference.
4. [MLX stream synchronization](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/device.cpp) commits a command buffer and calls `waitUntilCompleted`. [Apple documents](https://developer.apple.com/documentation/metal/mtlcommandbuffer/waituntilcompleted()) that this waits for that command buffer and its completion handlers. This documentation alone does not establish the order in which completion handlers of earlier buffers finish.

The [measured diagnostic](mlx-stream-sync-memory-result-v1.md) observed the lower B4 active count after explicit stream synchronization in three processes. A separate [full-codec experiment](mlx-stream-sync-runtime-result-v1.md) found a 10–16% B4 block median slowdown in three pairs when that synchronization followed every nonempty evaluation. Neither result proves allocation ownership or qualifies a production fix. The immediate and post-barrier measurements both remain evidence under the [predeclared plan](mlx-live-memory-plan-v1.md), and the existing 1.05 criterion is unchanged.
