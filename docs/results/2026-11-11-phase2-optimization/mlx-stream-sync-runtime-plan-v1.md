# MLX runtime synchronization candidate diagnostic

The [memory probe](mlx-stream-sync-memory-result-v1.md) found that an explicit same-stream synchronization after block evaluation consistently reaches the settled active-memory snapshot. Test a source-isolated runtime variant that calls the pinned MLX synchronization API after each nonempty `evaluate`, with its existing already-pinned transitive `mlx-sys` package declared directly for this diagnostic. All tensor math, model semantics and tolerances remain unchanged; this adds a command-buffer completion wait and may materially increase latency or alter error behavior.

Build the isolated variant and compare it with the existing qualified MLX runtime in three alternating fresh process pairs of the unchanged full codec benchmark. Preserve all batches/scopes, first-operation and steady-state timings, host/active memory, output identities, activity and thermal observations. Compare the existing immediate memory probe as well as teardown and verify trained float traces against the pinned oracle before proposing integration. No tolerance change or 78-cell gate follows from this diagnostic. If timings or resource behavior do not justify the synchronization, stop and retain the result. Production changes require deliberate dependency/FFI review and the full Linux-first, Apple-second gates.
