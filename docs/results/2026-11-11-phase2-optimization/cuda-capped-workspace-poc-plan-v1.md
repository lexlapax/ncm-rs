# CUDA capped-workspace diagnostic plan

After the zero-workspace result, compare a 2,621,440-byte (2.5 MiB) heuristic workspace limit against 4 MiB for the same 12 strict-FP32 fused projection/bias shapes. The cap was selected post hoc because the largest selected 4 MiB algorithm reported 2,187,264 bytes; heuristic choices may still change. This is an exploratory diagnostic, not a gate or a production change.

Apply [the patch](cuda-capped-workspace-poc-v1.patch) to the committed zero-workspace diagnostic source; the generated source SHA-256 is `af7b9d06a1ca3d0c30db8eeb1c91394993e5d170e924d7b1948d1a3a8061e3b3`. Compile with `/opt/cuda/bin/nvcc -std=c++17 -O2 -ccbin /usr/bin/g++-15 -x cu SOURCE -lcublasLt -o BINARY`. Run three fresh processes, each five warmups and 30 interleaved GPU-event and host timings per mode per shape. Check all outputs under the existing diagnostic tolerance and record heuristic availability, workspace sizes, process results and sampled activity. Preserve all failures. The shared 4 MiB test allocation does not measure pool savings, and fixed initialization order precludes a cold-start comparison. Any production candidate needs separate native lifecycle, full-codec, parity and Linux then Apple gates.
