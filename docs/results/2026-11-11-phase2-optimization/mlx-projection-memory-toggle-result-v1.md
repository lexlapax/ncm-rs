# MLX projection memory toggle result

Three fresh processes per version compared the existing fused MLX projection/bias with the isolated separate matmul and add. At batch-four resident-block, the fused version's immediate active bytes were 69,702,948 in all three runs; the separate version produced 59,970,860 once and 69,702,948 twice. The median ratio of separate to fused was 1.000. After the extra device barrier, all runs were near 59,970,832 bytes, except the first separate run at 59,970,864. The 10 ms and 100 ms values were similarly near 59,970,828–59,970,860. This does not establish that the projection operation causes or fixes the immediate observation.

All 12 batch/scope rows and all snapshot stages are retained. Token, code, available output-ID and retained-latent hashes match, and active bytes return to zero after all drops. The block's floating-point output was not compared, and timing was not measured. The [prior matched baseline](apple-gate18-results-v1.md) has 65,835,532 immediate bytes for this block; this toggle is a separate experiment, not a paired baseline gate or a reason to waive the 1.05 limit. Because the toggle does not consistently improve the target observation, no production change or further timing qualification follows.

Fourteen process-activity samples and before/after thermal observations were retained; no thermal warning was reported, but desktop activity was present. The reused fused probe binary and source match the previously archived matched-memory experiment. The alternate was built in a separate worktree from the reviewed [patch](mlx-projection-memory-toggle-v1.patch). [Review script](mlx-projection-memory-toggle-review-v1.py) checks all six report hashes, identities, four snapshot stages and cleanup.
